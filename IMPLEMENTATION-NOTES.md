# Implementation Notes: Kanban Project Management & Client Collaboration App

## Implicit Decisions

| Decision | Rationale | Affected Files |
|----------|-----------|----------------|
| App lives in `kanban-app/` sibling to the unrelated `frontend/` (QuantumStock) | Workspace root is a multi-project repo; scaffolding into a clean subdirectory avoids conflicts | `kanban-app/**` |
| **No Docker (user directive).** Dev DB = MongoDB Atlas (user provides `MONGODB_URI`); local fallback default `mongodb://127.0.0.1:27017/kanban` | User required full-cloud, no containers; Docker Desktop was stopped and the previously created `kanban-mongo` container/volume were removed | `src/lib/db.ts`, `.env.local` |
| First registered account becomes global `admin` (bootstrap convention); everyone else registers as `team`; `client` accounts are created by admins/assigned per project | Self-registration must not grant stakeholder review powers by default | `src/app/api/auth/register/route.ts`, `src/lib/services/users.ts` |
| Auth = `jose` HS256 JWT in httpOnly sameSite=lax cookie `kanban_session` (7 days), passwords hashed with `bcryptjs`, no email verification | Spec requires simple email/password + secure cookie, MVP speed | `src/lib/auth.ts`, `src/app/api/auth/*` |
| Edge `proxy.ts` (Next 16 renamed middleware) only checks JWT validity for page gating; deep RBAC (project membership/role) enforced inside every API route/server action | Edge proxy has no DB access (models aren't edge-compatible); defense in depth | `src/proxy.ts`, `src/lib/rbac.ts` |
| Storage driver abstraction: uploads REQUIRE the R2/S3 credentials (`R2_*` env vars) - presigned PUTs when configured, and with no credentials the upload flow refuses with `ApiError(503, STORAGE_UNCONFIGURED_MESSAGE)` (UI = calm toast). No local upload fallback (cloud-only, user directive); legacy files in `.data/uploads` remain downloadable through the auth-checked `/api/files/[...key]` route | Full upload flow is E2E-verifiable WITHOUT Cloudflare credentials (the refusal IS the assertion); identical client contract | `src/lib/storage.ts`, `src/app/api/upload/*`, `src/app/api/files/[...key]/route.ts` |
| `R2_PUBLIC_BASE` optional: when unset, ALL attachments (R2 too) stream through `/api/files/[...key]` which validates ticket→project membership per request | Keeps stakeholder-only attachments private even without a CDN | `src/app/api/files/[...key]/route.ts` |
| Constants/DTOs live in `src/lib/types.ts` (pure, client-safe); Mongoose models import & re-export them | Client components must never import mongoose-typed modules | `src/lib/types.ts`, `src/lib/models.ts` |
| Ticket column identity = canonical string keys `todo | in_progress | in_review | done` + numeric `order` per column; move endpoint applies a reindex map | Stable ids survive renames; drag reorders are small map updates | `src/lib/services/tickets.ts` |
| Activity log = embedded `activity` subdocument array; `review` is a structured subdoc + `review`-typed activity entries; only project `client` members may call the review endpoint (global admins explicitly excluded) | Strict spec rule: review authority belongs to stakeholders | `src/lib/rbac.ts`, `src/lib/services/tickets.ts` |
| Server Actions (`"use server"` + Zod) handle project & member management; REST API routes handle tickets/review/move/uploads | Client-side optimistic DnD + file uploads need fetch semantics | `src/app/actions/*`, `src/app/api/*` |
| Hand-rolled Radix wrappers instead of shadcn CLI; theme is LIGHT-first (white surfaces default) with a `dark` override on `[data-theme="dark"]` and a pre-paint inline script | Lean deps, explicit tokens for GitHub/Linear aesthetic | `src/components/ui/*`, `src/app/globals.css` |
| `lucide-react@1.70` removed the `Loader2` alias - all spinners use `LoaderCircle` | Verified against installed package .d.ts | all components |
| React-compiler-era lint rules respected: render-time `Date.now()` moved to server serializer (`TicketDTO.overdue`); localStorage-backed UI prefs use `useSyncExternalStore` stores | `react-hooks/purity` + `set-state-in-effect` errors in Next's ESLint config | `src/lib/serialize.ts`, `src/lib/theme-store.ts`, `src/components/board/board-workspace.tsx` |
| Members dialog remounts via `key={open ? "open" : "closed"}` and re-syncs member state during event handlers instead of effects | Same lint constraint; avoids stale-state divergence | `src/components/board/*` |
| npm installs require `--include=dev` (user-level `C:\Users\DUNG\.npmrc` sets `omit=dev`; user config left untouched per global-rules) | Prevents "typescript missing" regressions | package.json |
| **Rebrand: OrcaBoard → DymTicket** (user directive). Design is now light-first (white surfaces default; dark mode retained as `[data-theme="dark"]` override), with brand accents built on indigo→violet→fuchsia **linear gradients** exposed as Tailwind v4 `@utility` classes (`bg-gradient-primary/banner/soft/mesh`, `text-gradient-primary`, `elev-card/dialog`) so `hover:` variants work. Unsplash placeholders (`images.unsplash.com` via `next/image` + `remotePatterns`) decorate the auth split panel and dashboard empty states; project cards carry deterministic gradient covers derived from the project name (no external request per card). | User asked for a clean white tone, gradient accents, imagery and the new name | `globals.css`, `layout.tsx`, `theme-store.ts`, `auth-form.tsx`, `app-shell.tsx`, `projects-view.tsx`, `board-workspace.tsx`, `button.tsx`, `dialog.tsx`, `not-found.tsx`, `next.config.ts` |
